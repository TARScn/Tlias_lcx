# 三层架构详解（基于 Spring Boot 项目）

## 一、什么是三层架构？

**三层架构（Three-Tier Architecture）** 是一种软件设计模式，将应用程序划分为三个逻辑层次，每一层各司其职、职责单一，层与层之间通过接口进行通信。这种分层方式使得代码**高内聚、低耦合**，便于维护、测试和扩展。

在 Spring Boot 项目中，三层架构通常分为：

| 层次 | 名称 | 职责 |
|------|------|------|
| **Controller 层** | 控制层 / 表现层 | 接收请求、响应数据 |
| **Service 层** | 业务逻辑层 | 处理核心业务逻辑 |
| **Mapper 层** | 数据访问层 / 持久层 | 操作数据库（CRUD） |

此外，还有一个辅助层：

| 层次 | 名称 | 职责 |
|------|------|------|
| **POJO 层** | 实体类层 | 定义数据模型（Java Bean） |

## 三、各层详解（结合项目代码）

### 1. POJO 层 —— 实体类

**作用**：定义与数据库表对应的 Java 对象，封装数据。

**文件**：[`Dept.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/pojo/Dept.java)

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
public class Dept {
    private Integer id;           // 部门ID
    private String name;          // 部门名称
    private LocalDateTime createTime;   // 创建时间
    private LocalDateTime updateTime;   // 更新时间
}
```

- 使用 Lombok 注解 `@Data` 自动生成 getter/setter/toString 等方法
- 字段与数据库 `dept` 表的列一一对应

**文件**：[`Result.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/pojo/Result.java)

```java
@Data
public class Result {
    private Integer code;     // 状态码（1=成功，0=失败）
    private String message;   // 提示信息
    private Object data;      // 返回的数据
    // ... 静态工厂方法 success() / error()
}
```

- 统一封装后端响应结果，前端可据此判断请求是否成功

---

### 2. Controller 层 —— 控制层

**作用**：接收 HTTP 请求，调用 Service 层处理业务，将结果返回给前端。

**文件**：[`DeptController.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/controller/DeptController.java)

```java
@RestController
public class DeptController {

    @Autowired
    private DeptService deptService;   // 注入 Service 层

    @GetMapping("/depts")
    public Result list() {
        System.out.println("查询全部部门数据");
        List<Dept> deptlist = deptService.findAll();  // 调用 Service
        return Result.success(deptlist);               // 统一响应
    }
}
```

**关键点**：
- `@RestController` —— 标记为控制器，返回 JSON 数据
- `@Autowired` —— 依赖注入，将 Service 实现类注入进来
- `@GetMapping("/depts")` —— 处理 GET 请求，路径为 `/depts`
- Controller 只负责**接收请求**和**返回响应**，不处理业务逻辑

---

### 3. Service 层 —— 业务逻辑层

**作用**：处理核心业务逻辑，调用 Mapper 层操作数据库。

#### 接口

**文件**：[`DeptService.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/DeptService.java)

```java
public interface DeptService {
    /*
     * 查询全部部门数据
     */
    List<Dept> findAll();
}
```

- 定义业务方法的**接口**，便于解耦和面向接口编程

#### 实现类

**文件**：[`DeptServiceImpl.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/impl/DeptServiceImpl.java)

```java
@Service
public class DeptServiceImpl implements DeptService {

    @Autowired
    private DeptMapper deptMapper;   // 注入 Mapper 层

    @Override
    public List<Dept> findAll() {
        return deptMapper.findAll(); // 调用 Mapper 查询数据库
    }
}
```

**关键点**：
- `@Service` —— 标记为 Service 层组件，交给 Spring 管理
- 实现 `DeptService` 接口，编写具体业务逻辑
- 调用 Mapper 层的方法与数据库交互
- 如果业务复杂（如事务、校验、计算等），都在此层处理

---

### 4. Mapper 层 —— 数据访问层

**作用**：直接与数据库交互，执行 SQL 语句。

**文件**：[`DeptMapper.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/mapper/DeptMapper.java)

```java
@Mapper
public interface DeptMapper {

    /*
     * 查询全部部门数据
     */
    @Select("select * from dept order by update_time desc;")
    List<Dept> findAll();
}
```

**关键点**：
- `@Mapper` —— 标记为 MyBatis 的 Mapper 接口
- `@Select("SQL语句")` —— 直接编写 SQL，MyBatis 自动执行并映射结果
- 方法返回值 `List<Dept>` 会自动将查询结果封装为 Java 对象

## 四、三层架构调用流程

```
客户端（浏览器）
    │
    ▼
┌─────────────────────┐
│   Controller 层     │  ← 接收 HTTP 请求
│  (DeptController)   │
└─────────┬───────────┘
          │ 调用
          ▼
┌─────────────────────┐
│   Service 层        │  ← 处理业务逻辑
│  (DeptServiceImpl)  │
└─────────┬───────────┘
          │ 调用
          ▼
┌─────────────────────┐
│   Mapper 层         │  ← 操作数据库
│  (DeptMapper)       │
└─────────┬───────────┘
          │
          ▼
      数据库 (MySQL)
```

**以"查询全部部门"为例的完整流程**：

1. 浏览器发送 `GET /depts` 请求
2. [`DeptController`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/controller/DeptController.java:23) 的 `list()` 方法接收请求
3. Controller 调用 [`deptService.findAll()`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/DeptService.java:8)
4. [`DeptServiceImpl`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/impl/DeptServiceImpl.java:16) 执行 `findAll()`，调用 `deptMapper.findAll()`
5. [`DeptMapper`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/mapper/DeptMapper.java:14) 执行 SQL `select * from dept`
6. 结果逐层返回，最终 Controller 将数据封装为 [`Result`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/pojo/Result.java:18) 返回给前端

## 五、三层架构的优势

| 优势 | 说明 |
|------|------|
| **职责单一** | 每层只关注自己的职责，Controller 不写 SQL，Mapper 不处理请求 |
| **易于维护** | 修改数据库逻辑只需改 Mapper 层，不影响上层 |
| **易于测试** | 可以单独测试每一层（单元测试） |
| **代码复用** | Service 层可被多个 Controller 调用 |
| **解耦性强** | 层与层之间通过接口通信，替换实现类不影响其他层 |

## 六、常用注解列表及解释

### 6.1 Spring 核心注解

| 注解 | 位置 | 作用 |
|------|------|------|
| `@Component` | 类 | 将类标记为 Spring 管理的通用组件 |
| `@Service` | Service 实现类 | 标记为业务层组件 |
| `@Controller` | Controller 类 | 标记为控制层组件（返回视图） |

| `@Repository` | DAO 类 | 标记为数据访问层组件 |

## 七、总结

三层架构是 Java Web 开发中最经典、最基础的设计模式之一。通过本项目中的部门管理功能，可以清晰地看到：

- **Controller** 负责"接"和"返"（接收请求、返回响应）
- **Service** 负责"算"（处理业务逻辑）
- **Mapper** 负责"存"（操作数据库）
- **POJO** 负责"装"（封装数据）

掌握三层架构，是理解 Spring Boot 项目的基础，也是后续学习微服务、DDD（领域驱动设计）等更复杂架构的基石。
