# 增删改查（CRUD）逻辑与原理详解

## 一、什么是 CRUD？

**CRUD** 是 **C**reate（创建）、**R**ead（查询）、**U**pdate（修改）、**D**elete（删除）四个单词的缩写，是软件系统中最基础、最核心的数据操作能力。几乎所有业务系统都围绕 CRUD 展开。

本项目以 **部门管理（Dept）** 为例，完整实现了对部门数据的增删改查操作。

---

## 二、CRUD 整体架构

所有 CRUD 操作均遵循三层架构的调用链路：

```
客户端（浏览器/前端）
    │  HTTP 请求（GET/POST/PUT/DELETE）
    ▼
┌─────────────────────────────┐
│   Controller 层（控制层）    │  ← 接收请求、解析参数、返回响应
│   DeptController.java       │
└──────────┬──────────────────┘
           │ 调用 Service 接口
           ▼
┌─────────────────────────────┐
│   Service 层（业务逻辑层）    │  ← 处理业务逻辑（如补全时间）
│   DeptService.java          │
│   DeptServiceImpl.java      │
└──────────┬──────────────────┘
           │ 调用 Mapper 接口
           ▼
┌─────────────────────────────┐
│   Mapper 层（数据访问层）    │  ← 执行 SQL 操作数据库
│   DeptMapper.java           │
└──────────┬──────────────────┘
           │
           ▼
         数据库 (MySQL)
```

## 三、CRUD 各操作详解

### 3.1 查询全部 —— Read（查询）

#### Controller 层

**文件**：[`DeptController.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/controller/DeptController.java:30)

```java
@GetMapping("/depts")
public Result list() {
    System.out.println("查询全部部门数据");
    List<Dept> deptlist = deptService.findAll();
    return Result.success(deptlist);
}
```

- `@GetMapping("/depts")` —— 处理 `GET /depts` 请求
- 调用 `deptService.findAll()` 获取所有部门列表
- 将结果封装到 `Result.success(deptlist)` 返回给前端

#### Service 层

**接口**：[`DeptService.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/DeptService.java:9)

```java
List<Dept> findAll();
```

**实现类**：[`DeptServiceImpl.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/impl/DeptServiceImpl.java:18)

```java
@Override
public List<Dept> findAll() {
    return deptMapper.findAll();
}
```

- 直接调用 Mapper 层查询，无额外业务逻辑

#### Mapper 层

**文件**：[`DeptMapper.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/mapper/DeptMapper.java:18)

```java
@Select("select id,name,create_time,update_time from dept order by update_time desc;")
List<Dept> findAll();
```

- `@Select` 注解直接编写 SQL 查询语句
- MyBatis 自动执行 SQL 并将结果集映射为 `List<Dept>` 对象
- 按 `update_time` 降序排列，最新的数据排在最前面

### 3.2 根据 ID 查询单条 —— Read（查询）

#### Controller 层

**文件**：[`DeptController.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/controller/DeptController.java:65)

```java
@GetMapping("/depts/{id}")
public Result getInfo(@PathVariable Integer id) {
    System.out.println("根据id查询部门数据:"+id);
    Dept dept = deptService.getInfoById(id);
    return Result.success(dept);
}
```

- `@GetMapping("/depts/{id}")` —— 路径中包含 `{id}` 占位符
- `@PathVariable Integer id` —— 从 URL 路径中提取 `id` 参数
- 例如请求 `GET /depts/1`，则 `id = 1`

#### Service 层

**实现类**：[`DeptServiceImpl.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/impl/DeptServiceImpl.java:36)

```java
@Override
public Dept getInfoById(Integer id) {
    Dept dept = deptMapper.getInfoById(id);
    return dept;
}
```

#### Mapper 层

**文件**：[`DeptMapper.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/mapper/DeptMapper.java:36)

```java
@Select("select id,name,create_time,update_time from dept where id=#{id};")
Dept getInfoById(Integer id);
```

- `#{id}` —— MyBatis 参数占位符，会自动替换为传入的 `id` 值
- 返回单个 `Dept` 对象（若不存在则返回 `null`）

### 3.3 新增部门 —— Create（创建）

#### Controller 层

**文件**：[`DeptController.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/controller/DeptController.java:53)

```java
@PostMapping("/depts")
public Result add(@RequestBody Dept dept) {
    System.out.println("添加部门数据:"+dept);
    deptService.add(dept);
    return Result.success();
}
```

- `@PostMapping("/depts")` —— 处理 `POST /depts` 请求
- `@RequestBody Dept dept` —— 将请求体中的 JSON 数据自动反序列化为 `Dept` 对象
- 前端发送的 JSON 示例：`{"name": "技术部"}`

#### Service 层

**实现类**：[`DeptServiceImpl.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/impl/DeptServiceImpl.java:28)

```java
@Override
public void add(Dept dept) {
    // 补全时间
    dept.setCreateTime(java.time.LocalDateTime.now());
    dept.setUpdateTime(java.time.LocalDateTime.now());
    deptMapper.add(dept);
}
```

- **业务逻辑**：前端只传了 `name`，Service 层补全 `createTime` 和 `updateTime` 两个时间字段
- 这是 Service 层的典型职责 —— 处理 Controller 和 Mapper 之间的业务逻辑

#### Mapper 层

**文件**：[`DeptMapper.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/mapper/DeptMapper.java:30)

```java
@Insert("insert into dept(name,create_time,update_time) values(#{name},#{createTime},#{updateTime});")
void add(Dept dept);
```

- `@Insert` 注解执行插入 SQL
- `#{name}`、`#{createTime}`、`#{updateTime}` 从传入的 `Dept` 对象中自动取值
- `id` 字段为数据库自增主键，无需手动插入

### 3.4 修改部门 —— Update（更新）

#### Controller 层

**文件**：[`DeptController.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/controller/DeptController.java:72)

```java
@PutMapping("depts")
public Result update(@RequestBody Dept dept) {
    System.out.println("修改部门数据:"+dept);
    deptService.update(dept);
    return Result.success();
}
```

- `@PutMapping("depts")` —— 处理 `PUT /depts` 请求
- `@RequestBody Dept dept` —— 接收 JSON 请求体，包含 `id` 和 `name`
- 前端发送的 JSON 示例：`{"id": 1, "name": "研发部"}`

#### Service 层

**实现类**：[`DeptServiceImpl.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/service/impl/DeptServiceImpl.java:42)

```java
@Override
public void update(Dept dept) {
    // 补全时间
    dept.setUpdateTime(java.time.LocalDateTime.now());
    deptMapper.update(dept);
}
```

- **业务逻辑**：补全 `updateTime` 为当前时间
- 注意：`createTime` 在修改时不需要更新，只更新 `name` 和 `updateTime`

#### Mapper 层

**文件**：[`DeptMapper.java`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/mapper/DeptMapper.java:42)

```java
@Insert("update dept set name=#{name},update_time=#{updateTime} where id=#{id};")
void update(Dept dept);
```

> ⚠️ **注意**：这里使用了 `@Insert` 注解来执行 `update` SQL 语句，虽然功能上可以正常工作（MyBatis 执行的是 SQL 语句本身，不校验注解名称），但**规范做法**应该使用 `@Update` 注解。建议修改为：
> ```java
> @Update("update dept set name=#{name},update_time=#{updateTime} where id=#{id};")
> void update(Dept dept);
> ```

- `where id=#{id}` —— 根据 ID 定位要修改的记录
- 只修改 `name` 和 `update_time` 两个字段

## 四、CRUD 请求方式对照表

| 操作 | HTTP 方法 | 请求路径 | 请求参数方式 | 对应 SQL |
|------|-----------|----------|-------------|----------|
| 查询全部 | `GET` | `/depts` | 无 | `SELECT` |
| 查询单条 | `GET` | `/depts/{id}` | 路径参数 `@PathVariable` | `SELECT ... WHERE id=?` |
| 新增 | `POST` | `/depts` | 请求体 JSON `@RequestBody` | `INSERT` |
| 修改 | `PUT` | `/depts` | 请求体 JSON `@RequestBody` | `UPDATE` |
| 删除 | `DELETE` | `/depts` | 请求参数 `?id=1` | `DELETE` |

## 五、CRUD 核心原理

### 5.1 HTTP 方法与 RESTful 风格

本项目遵循 **RESTful API** 设计规范，使用不同的 HTTP 方法表示不同的操作：

| HTTP 方法 | 含义 | 幂等性 | 安全性 |
|-----------|------|--------|--------|
| `GET` | 查询资源 | ✅ 幂等 | ✅ 安全（不修改数据） |
| `POST` | 创建资源 | ❌ 非幂等 | ❌ 不安全 |
| `PUT` | 更新资源 | ✅ 幂等 | ❌ 不安全 |
| `DELETE` | 删除资源 | ✅ 幂等 | ❌ 不安全 |

> **幂等**：多次执行同一操作，结果相同。
> **安全**：操作不会修改服务器上的数据。

### 5.2 参数绑定机制

Spring 提供了多种方式将请求中的数据绑定到 Controller 方法的参数上：

| 注解 | 数据来源 | 示例 |
|------|---------|------|
| `@PathVariable` | URL 路径 | `/depts/{id}` → `id=1` |
| `@RequestParam` | 查询参数 | `/depts?id=1` → `id=1` |
| `@RequestBody` | 请求体 JSON | `{"name":"技术部"}` → `Dept` 对象 |
| 无注解（默认） | 查询参数 | `/depts?id=1` → `id=1`（按参数名匹配） |

### 5.3 MyBatis 自动映射原理

MyBatis 通过注解或 XML 配置，自动完成以下工作：

1. **参数绑定**：`#{name}` 从传入对象中读取 `name` 属性值，替换到 SQL 中
2. **结果映射**：`SELECT` 查询结果集的列名，自动映射到 Java 对象的同名属性
   - 数据库 `create_time` → Java `createTime`（驼峰命名映射）
   - 数据库 `name` → Java `name`

### 5.4 统一响应封装

所有 CRUD 操作都返回 [`Result`](../tlias-web-management/src/main/java/com/lcx/tlias_web_management/pojo/Result.java) 对象，前端通过 `code` 字段判断操作是否成功：

```java
// 查询成功，携带数据
return Result.success(deptlist);   // code=1, message="success", data=部门列表

// 新增/修改/删除成功，无需数据
return Result.success();           // code=1, message="success", data=null

// 操作失败
return Result.error();             // code=0, message="error"
```

## 六、CRUD 常用注解列表及解释

### 6.1 HTTP 请求映射注解

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@GetMapping` | Controller 方法 | 映射 HTTP GET 请求，用于查询操作 |
| `@PostMapping` | Controller 方法 | 映射 HTTP POST 请求，用于新增操作 |
| `@PutMapping` | Controller 方法 | 映射 HTTP PUT 请求，用于修改操作 |
| `@DeleteMapping` | Controller 方法 | 映射 HTTP DELETE 请求，用于删除操作 |
| `@RequestMapping` | 类/方法 | 通用请求映射，可指定 method（`method = RequestMethod.GET`） |
| `@PatchMapping` | Controller 方法 | 映射 HTTP PATCH 请求，用于部分更新 |

### 6.2 参数绑定注解

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@PathVariable` | Controller 方法参数 | 从 URL 路径模板中取值，如 `/depts/{id}` |
| `@RequestParam` | Controller 方法参数 | 从请求参数中取值，如 `?page=1&size=10` |
| `@RequestBody` | Controller 方法参数 | 从请求体中获取 JSON 并反序列化为 Java 对象 |
| `@RequestHeader` | Controller 方法参数 | 从请求头中获取值，如 `@RequestHeader("token")` |
| `@RequestPart` | Controller 方法参数 | 获取 multipart/form-data 中的文件或数据 |
| `@CookieValue` | Controller 方法参数 | 从 Cookie 中获取值 |
| `@ModelAttribute` | Controller 方法参数 | 将请求参数绑定到 Java 对象（非 JSON 场景） |

### 6.3 MyBatis SQL 注解

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@Select` | Mapper 方法 | 配置查询 SQL 语句 |
| `@Insert` | Mapper 方法 | 配置插入 SQL 语句 |
| `@Update` | Mapper 方法 | 配置更新 SQL 语句 |
| `@Delete` | Mapper 方法 | 配置删除 SQL 语句 |
| `@Param` | Mapper 方法参数 | 为 SQL 参数命名，用于多个参数时区分 |
| `@Options` | Mapper 方法 | 配置额外选项，如 `useGeneratedKeys=true` 获取自增主键 |
| `@Result` | Mapper 方法 | 配置单个字段的结果映射关系 |
| `@Results` | Mapper 方法 | 配置多个字段的结果映射关系（一组 `@Result`） |
| `@ResultMap` | Mapper 方法 | 引用已定义的 `@Results` 映射 |
| `@One` | Mapper 方法 | 配置一对一关联查询 |
| `@Many` | Mapper 方法 | 配置一对多关联查询 |
| `@SelectKey` | Mapper 方法 | 配置主键回填（用于非自增主键场景） |

### 6.4 参数校验注解（JSR-303 / JSR-380 Bean Validation）

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@NotNull` | 字段/参数 | 校验值不能为 null |
| `@NotBlank` | 字符串字段 | 校验字符串不能为 null 且不能为空字符串（去空格后长度 > 0） |
| `@NotEmpty` | 集合/字符串 | 校验不能为 null 且长度/大小 > 0 |
| `@Size` | 字符串/集合 | 校验长度/大小在指定范围内，如 `@Size(min=2, max=10)` |
| `@Min` | 数字字段 | 校验最小值，如 `@Min(1)` |
| `@Max` | 数字字段 | 校验最大值，如 `@Max(100)` |
| `@Pattern` | 字符串字段 | 校验正则表达式，如 `@Pattern(regexp="^1[3-9]\\d{9}$")` |
| `@Email` | 字符串字段 | 校验是否为合法邮箱格式 |
| `@Valid` | 方法参数 | 启用参数校验（配合校验注解使用） |
| `@Validated` | 类/方法/参数 | Spring 增强版 `@Valid`，支持分组校验 |

**使用示例**：

```java
@PostMapping("/depts")
public Result add(@Valid @RequestBody Dept dept) {
    // 如果 dept.name 为 null 或空字符串，会自动返回 400 错误
    deptService.add(dept);
    return Result.success();
}
```

### 6.5 事务管理注解

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@Transactional` | 类/方法 | 声明事务，方法中的所有数据库操作要么全部成功，要么全部回滚 |
| `@EnableTransactionManagement` | 配置类 | 启用注解事务管理（Spring Boot 自动配置，通常无需手动添加） |

**使用示例**：

```java
@Service
public class DeptServiceImpl implements DeptService {

    @Override
    @Transactional  // 如果删除失败，新增操作也会回滚
    public void deleteAndAdd(Integer deleteId, Dept newDept) {
        deptMapper.deleteById(deleteId);
        deptMapper.add(newDept);
    }
}
```

### 6.6 日志注解

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@Slf4j` | 类 | Lombok 注解，自动生成 `log` 对象（`log.info()`、`log.debug()`） |
| `@Log4j2` | 类 | Lombok 注解，生成 Log4j2 日志对象 |

**使用示例**：

```java
@Slf4j
@Service
public class DeptServiceImpl implements DeptService {
    public void add(Dept dept) {
        log.info("添加部门: {}", dept);  // 替代 System.out.println
        // ...
    }
}
```

### 6.7 异常处理注解

| 注解 | 使用位置 | 作用 |
|------|---------|------|
| `@ExceptionHandler` | Controller 方法 | 处理 Controller 层抛出的特定异常 |
| `@ControllerAdvice` | 类 | 全局异常处理 / 全局数据绑定 |
| `@RestControllerAdvice` | 类 | `@ControllerAdvice` + `@ResponseBody`，返回 JSON 格式的异常信息 |
| `@ResponseStatus` | 异常类/方法 | 指定 HTTP 响应状态码 |

**全局异常处理示例**：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        log.error("系统异常: ", e);
        return Result.error();  // 统一返回错误响应
    }
}
```

## 七、CRUD 常见问题与最佳实践

### 7.1 常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 新增后返回的 id 为 null | 未配置主键回填 | 使用 `@Options(useGeneratedKeys=true, keyProperty="id")` |
| 修改操作使用了 `@Insert` | 注解名称不规范 | 应使用 `@Update` 注解 |
| 查询结果为空但没报错 | 数据库无对应数据 | 检查 SQL 条件或返回空集合而非 null |
| 参数绑定失败 | 参数名不匹配 | 使用 `@Param` 明确指定参数名 |
| JSON 反序列化失败 | 字段名不匹配 | 确保 JSON 字段名与 Java 属性名一致 |

### 7.2 最佳实践

1. **使用 `@Update` 代替 `@Insert` 执行 UPDATE 语句** —— 语义更清晰
2. **新增时使用 `@Options` 获取自增主键**：
   ```java
   @Options(useGeneratedKeys = true, keyProperty = "id")
   @Insert("insert into dept(name,create_time,update_time) values(...)")
   void add(Dept dept);
   ```
3. **使用 `@Slf4j` 替代 `System.out.println`** —— 日志更规范，便于生产环境排查问题
4. **对关键操作添加 `@Transactional` 事务注解** —— 保证数据一致性
5. **使用 `@Valid` 进行参数校验** —— 避免无效数据入库
6. **统一使用 `Result` 封装响应** —— 前端解析更友好

## 八、总结

本项目通过部门管理的 CRUD 功能，完整展示了 Spring Boot + MyBatis 的经典开发模式：

- **Controller 层**：使用 `@GetMapping`/`@PostMapping`/`@PutMapping`/`@DeleteMapping` 映射 RESTful 请求，使用 `@PathVariable`/`@RequestBody` 绑定参数
- **Service 层**：处理业务逻辑（如补全时间字段），调用 Mapper 层
- **Mapper 层**：使用 `@Select`/`@Insert`/`@Update`/`@Delete` 注解直接编写 SQL

掌握 CRUD 是 Java Web 开发的基础，理解其背后的 HTTP 协议、RESTful 风格、参数绑定、MyBatis 映射等原理，能够帮助你快速上手任何业务系统的开发。
